# 协作协议 v1.1 · 文档 + 证据（当前生效）

> **版本**：v1.1-docs　**状态**：ACTIVE
> 兼容读取 v1-docs 文档；从本版本开始，状态、批准和并发规则分别以 `governance.md`、`concurrency.md` 为准。

## 1. 原则

1. 遵循 `team/philosophy.md` 的最低充分秩序；规则成本必须小于它避免的漂移成本。
2. 每类事实只有一个权威来源；其他文档用路径 + revision 引用，不复制易漂移内容。
3. 显式记录假设、决定、问题、工作认领和验证证据。
4. 契约先行；行为变化同步规范、契约、实现、测试和交接。
5. 状态字符串不是批准证据；高风险交付物按 `team.yaml#approval_policies` 批准。
6. 对外副作用遵循 action mode，不从“开发任务”推导 push 或部署授权。

## 2. 文档头部

普通 DRAFT/notes 只要求最小头部：

```yaml
---
title: <标题>
role: <作者 role id>
status: DRAFT
version: 0.1
updated: YYYY-MM-DD
upstream: [<权威输入路径或 URI>]
downstream: [<消费者 role id>]
---
```

进入 `team.yaml#approval_policies` 的门禁型交付物再增加 `artifact_type` 和 `approver`；进入 `APPROVED` 时必须补 `source_revision` 与 `approval_evidence`。`reviewers` 只在确有受影响 reviewer 时记录，不为字段完整而虚构。旧文档按触碰原则迁移。项目 `STATE.md` 和 `WORKBOARD.md` 使用各自控制状态。

## 3. 交接说明

门禁型交付物按 `approval_policies.*.handoff_required` 提供 30 秒交接块：给谁、一句话、关键决策、需要注意、未决问题。普通临时记录不强制。易漂移的测试计数和运行状态必须同时写验证日期、命令和 revision；不确定时写“未知/待验证”。

## 4. 评审与批准

1. 作者完成自检后置 `IN_REVIEW`；门禁型交付物指定 approver，确有影响面时指定 reviewers。
2. reviewers 留下可追溯意见或确认。
3. approver 按 `governance.md` 决定批准、打回或阻塞，并填写 evidence。
4. orchestrator 验证字段、权限与门禁，不能凭流程身份替代批准者。
5. 下游只把 `APPROVED` 且 revision 匹配的文档作为正式输入。

## 5. Q/C 流程

- Q：提出者登记 `OPEN` → 等待角色回答 → 提出者或 test-engineer 验证落地 → `RESOLVED`。
- C：提出者登记 `PENDING` → 事实批准者 `APPROVED/REJECTED` → 作者实施并补齐影响面 → orchestrator 核验证据后置 `IMPLEMENTED`。
- 用户明确决定可直接作为裁决证据，但必须记录；不能只写“编排者裁定”。

## 6. 写入与并发

任何非只读任务先按 `concurrency.md` 在 `WORKBOARD.md` 认领。任务提示必须包含 action mode、base revision、允许写入范围、禁止范围、验收命令和产出位置。没有有效认领或发现未知 worktree 修改时，不开始覆盖性写入。

## 7. 提交与发布

- 默认只完成修改和验证，不自动 commit、push、部署或写外部工具。
- `integrate` 可在用户明确请求或项目已登记政策允许时提交。
- push、部署、生产迁移、外部通知必须使用 `publish` 且有明确授权。
- commit 推荐 `<type>:<scope> <summary>`；若项目已有规范，以项目规范为准。

## 8. 兼容迁移

- v1-docs 项目无需一次性改完历史文档。
- `LIVE` 按 `ACTIVE` 读取；新写入不再使用 `LIVE`。
- 缺审批字段只产生迁移 warning；文档下一次被实质修改时必须补齐。
- 新项目必须包含 `STATE.md`、`WORKBOARD.md`、`open-questions.md` 并选择 workflow profile。

## 9. 版本语义

- `team.yaml#team.version`：整个团队定义的结构发布版本；
- 协议版本：协作规则族的兼容版本，由 `CURRENT.md` 指向；
- 文档 frontmatter `version`：单份内容的修订号。

三者用途不同，不要求数值联动。`CURRENT.md` 指向的是协议入口；该入口与其引用的 philosophy/governance/concurrency/workflow 共同构成当前协议。
